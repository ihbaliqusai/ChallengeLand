# إعادة هيكلة تقدم اللاعب

## الفصل بين الأنظمة

الخبرة `XP` رصيد دائم يرفع المستوى. رتبة الخبرة عنوان يعبر عن رحلة المعرفة؛ الدوري ودرجته يعبران عن رصيد الكؤوس الحالي. ترتيب لوحة الصدارة موضع داخل قائمة اللاعبين، وليس رتبة الخبرة.

| المستوى | رتبة الخبرة |
| --- | --- |
| 1–4 | مستكشف |
| 5–9 | متعلم |
| 10–19 | عارف |
| 20–29 | باحث |
| 30–44 | موسوعي |
| 45–59 | حكيم |
| 60+ | أسطورة المعرفة |

احتُفظ بمنحنى الخبرة التراكمي السابق حتى لا يفقد اللاعبون مستوياتهم أو الشخصيات المفتوحة. حساب حدود المستويات أصبح مستقلاً وقابلاً للاختبار، مع بحث ثنائي لا يمر على جميع المستويات. `PlayerRank.xpForLevel` هو مرجع الحد التراكمي، و`xpIntoLevel` هو التقدم داخل المستوى.

| الدوري | الكؤوس |
| --- | --- |
| مبتدئ | 0–199 |
| برونزي | 200–499 |
| فضي | 500–999 |
| ذهبي | 1000–1799 |
| ماسي | 1800–2999 |
| خبير | 3000–4999 |
| أسطورة | 5000+ |

الدوريات المحدودة مقسمة إلى ثلاث درجات تبدأ بـIII ثم II ثم I. أعلى دوري مفتوح؛ لا يوجد سقف اصطناعي عند 99999 كأس. تُحفظ أفضل كؤوس اللاعب بشكل مستقل عن الرصيد الحالي.

## مكافآت النتائج

| الحدث | الخبرة الأساسية | الكؤوس |
| --- | --- | --- |
| إجابة صحيحة | +10 | تُحسب الدقة عند الفوز |
| إجابة خاطئة أو انتهاء مهلة إجابة محتسبة | +3 | تُحسب ضمن دقة المباراة |
| فوز محلي أو فردي | +80 | +22 |
| فوز أونلاين | +100 | +22؛ وتضاف +8 عند مواجهة بشرية |
| خسارة محلية | +20 | -10 في أول 8 مباريات، ثم -18 |
| خسارة أونلاين | +30 | -10 في أول 8 مباريات، ثم -18 |
| تعادل محلي / أونلاين | +40 / +50 | 0 |
| إتمام جلسة فرق محلية مشتركة | +40 | +6 دون نسبة فوز شخصية |
| انسحاب بعد بدء اللعب | لا مكافأة إكمال | عقوبة الخسارة |

مكافأة سلسلة الفوز تبدأ بالفوز الثالث: +2 ثم +4 حتى +10 لكل فوز. مكافأة الدقة تخص المباراة الفائزة وتحتاج خمس إجابات على الأقل: +3 عند 75% أو +5 عند 90%. لا تنخفض الكؤوس دون صفر. الخبرة المكتسبة سابقاً لا تُخصم بسبب الخسارة.

تحتاج مكافأة الإتمام والكؤوس إلى إجابة محتسبة واحدة على الأقل. الغرف الفارغة أو خروج الخصم قبل بدء المشاركة لا تمنح نتائج أو مكافآت مجانية. في جلسة الفرق المحلية المشتركة يجيب الجهاز عن جميع الفرق، لذلك تسجل جلسة محايدة للحساب وتحصل على مكافأة الإتمام دون إسناد انتصار أحد الفريقين إلى صاحب الحساب.

مكافآت نجوم الحملة والإنجازات منفصلة عن مكافآت اللعب الأساسية، وتحتاج مطالبة مسجلة حتى لا تُصرف مرتين. فتح شاشة النتيجة مجدداً لا يمثل مباراة جديدة.

## المشكلات التي عالجتها البنية الجديدة

- كانت الكؤوس تُحسب من كامل تاريخ اللاعب عند كل تحديث؛ تغير نسبة الفوز أو الدقة كان يغير مكافآت الماضي.
- كانت بعض المسارات تعامل التعادل كخسارة، مع احتمال تكرار نتيجة ومكافأة عند إعادة إنشاء شاشة Android.
- كانت خبرة الحملة سحابية وخبرة اللعب محلية؛ اختيار القيمة الأكبر كان يضيع إحدى الزيادتين.
- كانت لقطات المحفظة تحفظ XP والكؤوس أيضاً، وقد تطمس تقدم مباراة أحدث.
- كان `friendCode` غير مسموح في قواعد الملف العام رغم إرساله عند المزامنة.
- كانت لوحة المستوى تعيد ترتيب أول 200 لاعب بالكؤوس، فتغيب عنها حسابات لها خبرة مرتفعة وكؤوس قليلة.
- كانت الواجهة تختار أكبر رصيد كؤوس بين الجهاز والسحابة، فلا تعكس الخسائر، وقد تعرض المركز 201 كلاعب عالمي خارج عينة الاستعلام.
- كانت أسماء رتب الخبرة مطابقة لأسماء الدوريات، وكان تقييم 1000 الثابت يُعرض كمؤشر مهارة.
- كان مسار Android القديم يحسب المستوى من مجموع جوائز بالملايين، بينما Flutter يحسبه من XP؛ أصبحت هوية اللعب والواجهات تعتمد مستوى الخبرة نفسه، وتُقرأ بيانات الحساب بعد ربطه قبل نشرها.

## الحفظ والمزامنة

تُسجل نتائج اللعب بمعرّف ثابت للمباراة أو المحاولة أو جولة الغرفة. سجل النتائج يمنع تكرار صرف المكافآت، ويُعزل التقدم حسب هوية الحساب. لكل تثبيت عدادات مساهمة مستقلة عن الرصيد المعاد تحميله من السحابة.

`ProgressionService` يجمع فروقات مساهمات التثبيت داخل معاملة واحدة تشمل `users/{uid}` و`public_profiles/{uid}` ونقطة التأكيد تحت `users/{uid}/progressionDevices/{deviceId}`. إعادة المحاولة بعد فقد رد الشبكة لا تكرر الزيادة. ترحيل الرصيد القديم يتم مرة واحدة؛ التقدم الجديد يعتمد على الفروقات. ملف اللاعب والإحصاءات يقرآن `AppState.playerStats` نفسه.

هوية التثبيت محفوظة ذرياً في مجلد Android المستثنى من النسخ الاحتياطي. استعادة تفضيلات الحساب على جهاز آخر تُنشئ نقطة تأكيد جديدة وتبدأ مساهمته من الصفر، مع الاحتفاظ بإحصاءات اللاعب وإيصالاته؛ لذلك لا يُعاد احتساب رصيد النسخة المنقولة ولا يتشارك جهازان نقطة التأكيد نفسها. إعادة التشغيل وتبديل الحسابات على الجهاز نفسه يحافظان على المعرفات المحفوظة.

الخبرة والكؤوس لا تُكتب من عمليات حفظ العملات أو المشتريات. مطالبات خبرة الحملة تُؤكد مع تحديث الرصيد والملف العام داخل المعاملة نفسها، ثم تُعاد مزامنة الجهاز دون اعتبار الرصيد المستعاد مكافأة جديدة.

## نطاق الثقة والنشر

هذه البنية تصلح اتساق التقدم والتكرار والمزامنة، لكنها لا تحول محرك اللعب المحلي إلى خادم يتحقق من كل إجابة. النتائج المحلية ونتائج الغرف الحالية ما زالت تعتمد على بيانات العميل. لا ينبغي وصف لوحة الكؤوس بأنها مقاومة للتلاعب أو استخدام نتائجها وحدها لجوائز مالية. حماية منافسات عالية المخاطر تحتاج اعتماد النتائج على خادم ومراجعة بروتوكول الغرف، وهي مرحلة منفصلة عن اتساق الحفظ.

قواعد Firestore المرفقة يجب نشرها مع الإصدار حتى تُقبل حقول الملفات العامة ونقاط تأكيد التقدم الجديدة. لا يتطلب الترحيل تصفير أرصدة اللاعبين. لم تُعدل بيانات الإنتاج كجزء من اختبارات التطوير.

## التحقق المحلي

```powershell
flutter analyze
flutter test
flutter build apk --debug
.\android\verification\run_checks.ps1
```

اختبارات قواعد Firestore تستخدم المحاكي المحلي ومكتبة Firebase الرسمية فقط، وفق [دليل Firebase لاختبار القواعد](https://firebase.google.com/docs/firestore/security/test-rules-emulator).

شغّل المحاكي في نافذة PowerShell مستقلة بعد تثبيت Firebase CLI:

```powershell
firebase emulators:start --only firestore --project demo-challengeland-progression
```

ثم من جذر المشروع في نافذة ثانية:

```powershell
npm install --prefix build/progression-rules --no-audit --no-fund --save-dev @firebase/rules-unit-testing firebase
$env:FIRESTORE_EMULATOR_HOST = '127.0.0.1:8080'
node --test tools/test_progression_rules.cjs
```

إذا كان منفذ المحاكي مختلفاً، عدّل `FIRESTORE_EMULATOR_HOST` إلى المنفذ الظاهر عند تشغيله. استُخدم المنفذ 8188 أثناء هذه المراجعة. يستخدم الاختبار مشروع `demo-challengeland-progression` فقط، ويرفض عنواناً غير محلي. يتحقق من الحفظ الكامل للملفات العامة والخاصة و73 عداد مساهمة ضمن حد تقييم القواعد، ومن خسائر الكؤوس السالبة، ومنع وصول حساب إلى نقاط تأكيد حساب آخر، ورفض الحقول الخاصة في الملفات العامة والقيم والأنواع غير الصالحة.

اختبارات Java تُعيد ترجمة مصادر التقدم الحالية، وتغطي الأطوار العشرة والإجابات والنتائج المتكررة وتبديل الحسابات وفشل الحفظ والمكافآت المعلقة أثناء المزامنة. يلزم بناء Android أولاً لتوفير رفيق المتجر المترجم؛ باقي تفاصيل أدوات التحقق موجودة في `android/verification/README.md`.
